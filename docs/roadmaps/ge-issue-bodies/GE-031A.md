Task: GE-031A — Redesign task body generation and introduce central Task Contract (meta-process improvement)

Context:
We are running a large GovEngine roadmap (GE-001..GE-045) through Signposter. The current way of authoring task descriptions in the plan and the generated issue bodies leads to extreme duplication.

Almost every task body repeats large blocks:
- full Signposter status and rules
- Scope rules
- Implementation guidance
- Tests requirements
- Stop conditions
- Report back format
- Mutation boundaries

This wastes a massive number of tokens on every agent interaction.

Goal:
Investigate the current system for creating and managing task definitions in this roadmap, and redesign it for significantly lower token usage and better maintainability, while keeping full compatibility with how Signposter (planner, seed, scheduler, side-task mechanism, etc.) works.

What to investigate (minimum):
- Structure of ge-governed-runtime-kernel-mvp-plan.json (bodies embedded directly)
- ge-governed-runtime-kernel-mvp-seed-manifest.json and linkage to GitHub issues
- Pre-generated bodies in docs/roadmaps/ge-issue-bodies/
- How signposter planner validate / seed / side-task-plan / issue-factory work
- How the scheduler parses side-task / return-to / parent / mainline metadata from issue bodies
- How side tasks are selected vs mainline tasks

Direction (this is only an example, not strict requirement):
One promising direction is to extract all the common rules, scope constraints, reporting formats, mutation boundaries, safety rules etc. into a single central "Task Contract" document (e.g. `docs/roadmaps/GE-TASK-CONTRACT.md` with versioning).

Individual task definitions would then become much lighter — they would contain only the task-specific parts (Purpose, Concrete scope, Non-goals, specific acceptance criteria, validation command, depends_on) plus a reference to the contract version.

You are free (and encouraged) to analyze the current mechanisms and come up with the best solution after investigation. The key success criteria are:
- Dramatically reduced duplication / token usage for the remaining tasks in this roadmap.
- The new structure must still work well with existing Signposter tooling.
- After finishing this task, you must cleanly return to the mainline roadmap and continue normal work (starting from GE-031 or the appropriate next mainline task at that time), now using the improved format.

Rules for this meta-task:
- Use Signposter tools (planner, side-task-plan, issue-factory, labels, etc.) to perform changes wherever practical and safe.
- Do not break `signposter planner validate` or the ability to continue the existing mainline run.
- Prefer changes that affect remaining and future tasks.
- After completing the redesign and updating the relevant artifacts, return to normal mainline workflow.
- The next task you pick up after this one should be GE-031 (or the current next mainline task), and from that point the tasks should use the new lighter format.

After finishing this task you should have:
- A clear new contract/template system documented.
- Updated definitions/bodies for the remaining tasks (GE-031 onward) in the improved format.
- A clear final report stating that you are returning to mainline work on the next task using the rebuilt system.
